# Contributing to NotchGram

Issues and pull requests are welcome. For anything bigger than a bug fix,
open an issue first so we can agree on the approach before you write code.

## Setup

Follow [Build from source](README.md#build-from-source) in the README: Xcode 26+,
`brew install xcodegen jq`, your own `api_id`/`api_hash` from
[my.telegram.org](https://my.telegram.org) in `.env`, a `Config/Local.xcconfig`
with your own (or an empty) `DEVELOPMENT_TEAM`, then `make deps`.

Never commit `.env`, `Secrets.generated.swift` or any credential. Never paste
real chat content, phone numbers or account data into issues, commits or
screenshots.

## Commands

| Command | What it does |
| --- | --- |
| `make build` / `make run` | Debug build, then launch it (quits a running copy first) |
| `make test` | Unit tests |
| `make itest` | Headless integration harness against Telegram's **test DC** |
| `make quit` | Graceful quit. Never `kill -9` the app: TDLib keeps an encrypted SQLite database open |
| `make logs` | Stream the app's unified log |
| `make media` | Regenerate the README screenshots from demo data |

Debug builds have a demo mode (`NOTCHGRAM_DEMO=1`) that fills the panel with
fixture chats, so UI work and screenshots never need a real account.

## About the test DC

Automated tests never touch a real account. `make itest` uses Telegram's test
data centre with its reserved `99966XXXXX` numbers. Telegram's test-DC login
currently rejects its own documented code
([tdlib/td#3083](https://github.com/tdlib/td/issues/3083)), so the harness runs
the auth probe up to the code step and reports the live round trip as
*skipped*, with the reason. That is expected, not a failure. The incoming update
handling is covered offline by replaying fixtures in `make test`.

## Rules of the codebase

- **`project.yml` is the source of truth.** The `.xcodeproj` is generated by
  XcodeGen and gitignored. Never edit or commit it; change `project.yml` instead.
  To build under your own team, copy `Config/Local.xcconfig.example` to
  `Config/Local.xcconfig` (untracked): leave `DEVELOPMENT_TEAM` empty to sign
  ad-hoc, or set your own team ID there; no tracked file changes.
- Build through `make`, not by calling `xcodebuild` directly. Every flag in the
  Makefile is there for a reason.
- Swift 6 strict concurrency. Fix diagnostics properly; a targeted
  `nonisolated(unsafe)` with a stated invariant is fine, a blanket
  `@unchecked Sendable` is not.
- `TelegramCore` stays free of AppKit/SwiftUI (the headless harness compiles it).
- Every UI state must be reachable through the DebugBridge, not only through a
  physical hover.
- Before changing the panel, hover or scrolling code, read the relevant
  decision in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Many of them record
  a bug that is easy to reintroduce (D16, D38, D40 and D41, for example).
- English in code, comments, commits and docs. User-facing strings go through
  `L10n.s(english, russian)`.

## Commits and pull requests

- [Conventional commits](https://www.conventionalcommits.org): `feat:`, `fix:`,
  `refactor:`, `docs:`, `test:`, `chore:`, with an optional scope
  (`fix(chat): …`).
- One logical change per commit. Keep pull requests focused.
- `make test` must pass. For UI changes, include a screenshot or a short
  recording made with demo data.
- If your change overturns an architecture decision, update its row in
  `docs/ARCHITECTURE.md` and say why.

## Releases

Maintainer only: `make release VERSION=x.y.z` builds, signs with Developer ID,
notarizes and packages the DMG.
